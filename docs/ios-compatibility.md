# Совместимость с оригинальным VK TURN Proxy iOS

## Архитектурное требование

Совместимость с оригинальным **VK TURN Proxy iOS из TestFlight** обязательна для каждого серверного релиза. Пользователь должен иметь возможность импортировать профиль и установить туннель, используя оригинальный клиент независимо от наличия, подписи и доступности нашего SwiftUI-приложения.

Сервер сохраняет путь **DTLS-SRTP → UDP 56004 → WireGuard на 127.0.0.1:51820**, поведение транспорта и возможность обычного WireGuard-рукопожатия. Другие режимы можно добавлять параллельно с существующим. Изменение закреплённого SRTP-бинарника, параметров запуска, формата импорта или пути UDP-трафика требует повторной проверки на оригинальном клиенте.

Экспорт сохраняет `vkturnproxy://import?data=…`. Параметр `data` содержит JSON в Base64URL без padding. Контракт версии 1 использует `type: "connection"` и объект `settings` с именами полей `serverName`, `privateKey`, `peerPublicKey`, `tunnelAddress`, `allowedIPs`, `peerAddress`, `vkLink` и `useSrtp: true`. `peerAddress` указывает на внешний SRTP endpoint, `tunnelAddress` содержит IPv4 клиента с `/32`, `allowedIPs` содержит `0.0.0.0/0`. Для подключения по-прежнему используются VK call URL и ключи WireGuard.

## Автоматические проверки

- [Эталонная ссылка](../tests/fixtures/upstream-ios-import.url) с тестовыми значениями сгенерирована функцией `build_link` из [upstream quick_link.py](https://github.com/anton48/vk-turn-proxy-ios/blob/0fddeef5b70044a0cf9bcd9fe093edfc4956d8c6/quick_link.py). Тест менеджера сравнивает экспорт с эталоном побайтно, а тест iOS Core проверяет импорт того же файла. Ключи и VK URL в файле синтетические.
- [Тест транспорта](../tests/ios-srtp.sh) проверяет соответствие релизу и параметрам systemd, скачивает используемый установщиком Linux amd64 бинарник и сверяет SHA-256. Go-код транспорта из [закреплённой ревизии оригинального клиента](https://github.com/anton48/vk-turn-proxy-ios/tree/0fddeef5b70044a0cf9bcd9fe093edfc4956d8c6/pkg/proxy/srtpwrap) устанавливает DTLS-SRTP-сессию с ним через loopback. Проверяются байты и границы UDP-датаграмм в обоих направлениях с синтетическим backend. Тест работает на отдельном Linux runner без VK, TURN relay, WireGuard-интерфейса и VPS.

## Приёмка серверного релиза на физическом iPhone

1. Подготовьте отдельный тестовый стенд с кандидатом на выпуск, рабочим WireGuard, доступным SRTP endpoint и временным пиром. Создайте ссылку штатным `client export … --srtp-endpoint … --vk-link-file …` с действующей ссылкой на тестовый VK-звонок. Храните ссылку импорта и ключи вне отчёта и CI.
2. Установите оригинальный VK TURN Proxy из TestFlight на физический iPhone. Откройте экспортированную ссылку в оригинальном приложении, подтвердите импорт и разрешите iOS добавить VPN-конфигурацию. Проверьте, что профиль импортирован в режиме SRTP и использует ожидаемый endpoint.
3. Подключитесь. На стенде проверьте свежее WireGuard-рукопожатие временного пира и рост счётчиков в обе стороны. С iPhone выполните запрос к заранее известному IPv4-ресурсу за туннелем и проверьте ответ. Отключите туннель, подключитесь заново и повторите проверку трафика.
4. Зафиксируйте дату, серверный коммит, версию и номер сборки TestFlight, модель iPhone, версию iOS и результаты импорта, рукопожатия, трафика и переподключения. Удалите временный пир и тестовый профиль. Приёмка считается пройденной после успешной проверки на устройстве.

Приёмка включает работу с реальным VK/TURN relay, WireGuard и iOS. Синтетический тест транспорта и XCTest проверяют свои участки отдельно. Подпись нашего приложения описана в [руководстве iOS](../ios/README.md#подпись-и-iphone).
