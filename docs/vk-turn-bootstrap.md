# Получение TURN credentials по ссылке VK

Issue #12 остаётся открытым для автоматического bootstrap. В текущей сборке импорт `vkturnproxy://import` сохраняет SRTP endpoint, параметры WireGuard и ссылку на звонок. Оригинальный клиент по-прежнему может использовать тот же формат. Для запуска собственного клиента требуется действующая пара TURN username/password с адресом реле и сроком действия от разрешённого поставщика. Получение credentials по ссылке отдельно не подтверждено.

## Что подтверждено

| Источник | Что предоставляет |
| --- | --- |
| Официальный VK ID iOS SDK | Вход пользователя в зарегистрированное приложение и результат авторизации VK ID. В открытом контракте SDK не обнаружена выдача TURN credentials для ссылки VK Calls. |
| Публичная схема VK API 5.199 | `calls.start` принимает пользовательский токен и создаёт звонок. Ответ содержит ссылки на звонок и может содержать `short_credentials` для входа по короткому ID. Их поля описывают ID, пароль звонка и ссылки. Полей TURN endpoint, username, password и expiry в этом ответе нет. |
| Оригинальный VK TURN Proxy iOS, закреплённая ревизия | Go-реализация получает TURN-параметры из ответа внутреннего сценария присоединения VK/OK. В исходниках есть ветки с чужими идентификаторами приложений и специальной обработкой CAPTCHA. Этот путь не подтверждает доступность того же API для зарегистрированного стороннего приложения. |

Источники. [VK ID iOS SDK](https://github.com/VKCOM/vkid-ios-sdk), [Методы Calls](https://github.com/VKCOM/vk-api-schema/blob/333481bd082ad747d4873ef4a77f9247097eeef0/calls/methods.json), [Ответ calls.start](https://github.com/VKCOM/vk-api-schema/blob/333481bd082ad747d4873ef4a77f9247097eeef0/calls/responses.json), [Модель short_credentials](https://github.com/VKCOM/vk-api-schema/blob/333481bd082ad747d4873ef4a77f9247097eeef0/calls/objects.json), [Транспорт оригинального клиента](https://github.com/anton48/vk-turn-proxy-ios/blob/0fddeef5b70044a0cf9bcd9fe093edfc4956d8c6/pkg/proxy/creds_vkcalls.go).

## Что нужно для реализации

Для стороннего App ID нужен подтверждённый VK контракт, который принимает приглашение в существующий звонок, выдаёт параметры TURN для разрешённого использования и определяет TTL, обновление, необходимые разрешения и продолжение после интерактивной проверки. Одна только авторизация VK ID этих сведений не даёт. Проверка публичных источников не исключает партнёрский API. Доступ к такому API и его документация для проекта отсутствуют.

Если VK предоставит поддерживаемый контракт, приложение сможет начать авторизацию из SwiftUI через официальный SDK или предоставленную VK системную веб-сессию. Пользователь сам проходит авторизацию и CAPTCHA в интерфейсе провайдера. Продолжение, отмена и истечение интерактивной сессии должны идти через документированные ответы провайдера. После выдачи приложение может проверять срок, сохранять параметры в уже используемую общую Keychain-группу и передавать их существующему Rust-транспорту. При обновлении требуется проверить новый TTL и завершить старую сессию согласно контракту провайдера. Статус VPN по-прежнему зависит от подтверждённого WireGuard-рукопожатия.

Исходники оригинального клиента используются как справочник по формату и транспорту. Они распространяются под GPLv3. В данном изменении исходники не копируются, не линкуются и не включаются в приложение. CI использует синтетические параметры и локальный стенд. Проверка с реальным VK ID, пользовательской CAPTCHA или частными API не проводилась.
